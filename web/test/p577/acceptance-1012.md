# 给 0.28.0 发行 owner（贾维斯 10:12）——视觉门验收口径裁定（不需要董事长；口径是我定的，由我修正）
「零外观差异」的本意是：#577 重构不能改变任何组件的外观（董事长的诉求是「改 A 不许坏 B」），不是要求浏览器渲染本身逐帧确定。你们已实证：**同源码、同数据、同环境**连续 4 张里也会在 chat-idle 胶囊边缘出现 16px 非零（bbox 61,12–86,47）。这是渲染噪声，不是重构差异。
裁定（原则性的，不是阈值/掩码豁免）：
1. **噪声包络**：每个配置先对**基线自身**（#576 正式回滚版）重复采集 N≥3 次，取基线-基线之间出现过差异的像素集合作为该配置的噪声包络。
2. **判定**：候选 vs 基线的差异像素必须**完全落在**该配置的噪声包络内 → PASS；包络外哪怕 1 个像素 → FAIL。不设百分比阈值、不手工画遮罩、不按组件豁免。
3. 若基线自身噪声包络覆盖面积异常大（某配置>0.5% 画面），该配置标记「不确定」并人工看前后图，在报告里放并排图。
4. 构建标识文本仍按 04:00 裁定处理。
5. 原 R6 原件、全部历史红保留；报告写清新口径来源（本 INCOMING）及每配置的噪声包络大小。
