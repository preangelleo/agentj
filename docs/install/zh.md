# 安装

四种装法装出来的是同一个 Agent J，装好以后都在手机上跟它说话。拿不准就选①。

## Windows {#windows}

适用于 Windows 10 和 Windows 11（64 位）。Agent J 运行在微软的 Linux 子系统（WSL2）里的 Ubuntu 上，安装命令会先把它装好，你不用提前准备。

### ① 自己装：一条命令 {#windows-self}

**什么时候选它：** Agent J 主机上还没有 AI 工具，或者你想自己动手。全程只用一个码：账户页空席位卡上的**安装码**（`AJI-` 开头）。

**预计时间：** 通常 15 到 30 分钟，大部分是在下载；第一次装 WSL 可能要重启一次。要你动手的部分加起来几分钟。

1. 在账户页 https://agentj.app/account/ 的空席位卡点「获取专属安装命令」，再点「复制安装命令」。在 Windows 上打开账户页，给的就是 PowerShell 那一条；不是的话点「换成 Windows（PowerShell）命令」。
2. 打开 PowerShell（开始菜单里搜 PowerShell，不用管理员身份），粘贴，回车。命令长这样：

   ```powershell
   $env:AGENTJ_CODE='AJI-…'; irm https://agentj.app/install.ps1 | iex
   ```
3. 照屏幕走。每一步开头都写着这是第几步、在做什么：

| 屏幕上 | 你要做的 |
|---|---|
| 安装码 | 命令里带了码就直接用；没带会让你粘贴一次（不显示） |
| WSL2 和 Ubuntu | 弹出管理员确认窗口时点同意；要重启就重启，重启后再粘贴同一条命令 |
| Ubuntu 用户 | 起个用户名（直接回车用默认的），设一个密码（输入时不显示，记住它） |
| 系统组件 | 不用做，Windows 上不问密码 |
| AI | 已经登录过 Claude Code 或 Codex 就直接用。没有就选一条路：连不上官方服务选 Agents Relay 中转（见[香港和中国大陆](/docs/install/#hk-cn)），能连就在浏览器里登录官方账号 |
| Agent J | 不用做：装好、启动后台服务、用同一个码绑定这个席位 |
| 手机 | 屏幕上出现二维码：用**你自己的手机**打开 https://m.agentj.app ，点「扫二维码」扫它 |
| 接上 AI | 不用做：AI 先真实回复一次才接上 |
| 永不休眠 | 显示要你自己在 PowerShell 里做的 Windows 电源设置；Ubuntu 里不改任何东西（[详细说明](/docs/keep-awake/#windows)） |

> **多一个选项**：AI 那一步的菜单里还有第 6 项「用 OpenCode 自带的免费模型先跑起来」：不登录、不填 key，先用起来；对话和代码会发给 OpenCode 和它的模型供应商。它优先选不拿对话训练的免费模型；免费模型有限流、随时可能下线，敏感工作请之后换成自己的模型（手机「模型与 Key」）。其他选项和默认推荐都不变。

4. 看到「✅ 全部完成」，就在手机上跟它打个招呼。以后要在Agent J 主机上用 `agentj`，从开始菜单打开「Ubuntu」，不是 PowerShell。

出了问题：

- 中途哪一步失败，屏幕上会写一行「怎么办：…」。修好后**粘贴同一条命令**，做完的步骤会跳过。
- 安装码只能用一次，24 小时内有效（卡片上写着到期时间）。
- 只差 AI 没接上：在「Ubuntu」里再运行一次 `curl -fsSL https://agentj.app/install.sh | bash`（不用带码），它只补这一步。
- 确认 systemd 已开启：后台服务靠它运行。在「Ubuntu」里运行 `ps -p 1 -o comm=`，应该显示 `systemd`。不是的话，在「Ubuntu」里运行 `printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf`（文件里 `[boot]` 下已经有 `systemd=true` 就跳过），再在 PowerShell 里运行 `wsl --shutdown`，重新打开「Ubuntu」后运行 `agentj service install`。安装命令会自己做这两步；`agentj service install` 和升级遇到没开 systemd 时，也会用一句话告诉你这两步。

### ② 让Agent J 主机上的 AI 帮你装 {#windows-ai}

**什么时候选它：** 你已经在 WSL 的 Ubuntu 里用 Claude Code、Codex 或 OpenCode，想让它替你操作、边装边解释。Windows 上 Agent J 只能装在 WSL2 里，装在 Windows 本身的 AI 会停下来告诉你；还没有 WSL 的话，选①更省事。

1. 已经买了席位：在账户页空席位卡上点「复制安装提示词」，发给 Ubuntu 里的 AI。
2. 还没买：把下面这句话原样发给它，它会带你注册账号、买席位：

```text
请用 curl 把 https://agentj.app/install.md 下载到本地，用读文件的工具完整读完，然后一步一步照着做，每一步开始前重读那一节。需要我动手的时候告诉我。
```

AI 每一步做什么、哪几步会停下来叫你，见[让 AI 装的时候](/docs/install/#ai-steps)。

### ③ 远程安装助手（云端） {#windows-assistant}

**什么时候选它：** 身边没人帮忙，Agent J 主机上也没有 AI，装到一半卡住了想问人。

现在这样用：

1. 照①的命令装。这条命令本身就是安装助手：每一步在做什么都写在屏幕上，出错时会写一行「怎么办：…」。照着修好，再粘贴同一条命令接着装。
2. 还是弄不明白，而 Agent J 已经装上了：在「Ubuntu」里运行下面这条命令。它把你的问题和去掉了密钥的体检结果发给我们服务器上的客服，一般几分钟内回你具体步骤。

```bash
agentj support ask "<你的问题>" --attach-doctor
```

3. 还没装上，或者连不上我们：发邮件到 feedback@agentj.app，写清卡在哪一步、报错原文，附上截图（先遮住安装码、key 和二维码）。

> **提示**：后续版本计划让云端助手直接在你的手机上给出下一步建议，你点了才执行。

### ④ 请人帮你装：在旁边或远程 {#windows-helper}

**什么时候选它：** 你不熟悉Agent J 主机或终端，有家人、朋友或同事能坐在旁边，或者通过视频通话、屏幕共享帮你。

现在的做法：

1. 帮手照①带着你做。码只在**你自己的**账户页复制，只粘在你自己的Agent J 主机上；远程帮的时候你共享屏幕、帮手口头指挥，码和 key 不要发进聊天。
2. 中途会弹出 Windows 的管理员确认窗口，可能还要重启一次。帮手提前跟你说一声，你就不会慌。
3. 扫二维码配手机，用**你自己的手机**。如果扫的是帮手的手机，它就成了这台Agent J 主机的遥控器：装完以后运行 `agentj devices` 找到它的设备号，再运行 `agentj revoke <设备号>` 把它移走。
4. 当时手机不在手边，或者扫码那一步没配上，不用重装：装好以后在账户页这台Agent J 主机的席位卡上点「添加遥控器」，用通行密钥确认，再用你的手机扫码。

> **提示**：一键帮手配对计划在后续版本推出：帮手用自己的手机临时连上，在手机上带你装完；你的手机配好、AI 接上以后，帮手自动断开。

## macOS {#macos}

## Linux {#linux}

适用于 Ubuntu、Debian 等常见发行版，台式机、笔记本和云服务器都可以。只能用 SSH 登录、没有桌面的云服务器，还要看[安装说明](https://agentj.app/install.md)里云服务器那一节。

1. 帮手照①带着你做。码只在**你自己的**账户页复制，只粘在你自己的Agent J 主机上；远程帮的时候你共享屏幕、帮手口头指挥，码和 key 不要发进聊天。
2. 要输入Agent J 主机密码的时候由你自己输，不要告诉帮手。
3. 扫二维码配手机，用**你自己的手机**。如果扫的是帮手的手机，它就成了这台Agent J 主机的遥控器：装完以后运行 `agentj devices` 找到它的设备号，再运行 `agentj revoke <设备号>` 把它移走。
4. 当时手机不在手边，或者扫码那一步没配上，不用重装：装好以后在账户页这台Agent J 主机的席位卡上点「添加遥控器」，用通行密钥确认，再用你的手机扫码。

> **提示**：一键帮手配对计划在后续版本推出：帮手用自己的手机临时连上，在手机上带你装完；你的手机配好、AI 接上以后，帮手自动断开。

## Olares 盒子 {#olares}

Agent J 也能装在 Olares 盒子上（Olares 1.12 或更新），数据留在盒子里。

- **装在盒子自己的 Ubuntu 上，用普通用户**（不用 root），和装云服务器一样。不要装进 Olares 应用里：在那些容器里，Agent J 的安全围栏起不来。
- **让它一直运行：** AI 会请你运行一次 `sudo loginctl enable-linger <用户名>`（密码你自己输），再重新登录一次，然后它把服务装好。
- **模型：** 用盒子自带的 **Olares Router**。在 Router 应用里新建一把 API key，AI 通过 DeepSeek 的 dsh 或 OpenCode 接上它，key 只粘贴在手机卡片里。见 [DeepSeek dsh](/docs/setup-agents/#dsh)。
- **远程维护：** 用官方的 LarePass VPN。助记词由你自己在 LarePass 里导入，绝不交给 AI。手机连 Agent J 不需要这个 VPN。
- **买来时已经预装了 Agent J？** 预装的只有软件。激活以后，你用自己的 Agent J 账号登录，自己建席位。

## 香港和中国大陆：AI 怎么选 {#hk-cn}

> **注意**：在香港和中国大陆，Claude Code、Codex 的官方服务通常连不上。一条命令装到 AI 那一步时会先测网络，连不上就推荐 **Agents Relay 中转**：先在 https://agentsrelay.net/onboard/ 注册、拿到 key，再回到终端粘贴（输入时不显示）。key 只粘在终端里，不要发进聊天，也不要告诉帮手。

中国大陆也可以用 OpenCode 加国产模型，见[装好 AI 命令行工具](/docs/setup-agents/)。

用火山方舟、Kimi、阿里百炼或 DeepSeek，或者还没决定买哪家：见[按你用的模型选](/docs/models/)。

## 让 AI 装的时候 {#ai-steps}

为什么要先下载、完整读完：有的 AI 用网页工具只读到一份摘要，摘要会把安全规矩和要停下来问你的地方省掉。它开始之前可能先跟你讲讲风险、问你要不要继续，这很正常。

如果别人已经给你付了一个席位，他会发你一句更长的话，里面带一个 `ajt_` 开头的设置码。那就直接发那一句，不用发上面这句。

接下来它会自己干活。遇到只有你本人能做的事，它会停下来，用你看得懂的话告诉你要做什么，等你说「好了」再继续。

`install.md` 是给 AI 看的安装说明，所以用英文写。这一页是同一套流程的大白话版，步骤编号跟它一一对应。

## 哪些事要你本人来做

AI 不会替你做下面这些事，也不会让你把密码、验证码、口令这类东西发给它。到了这些地方，它一定会停下来叫你：

- 设遥控器配对密码（安装结束时会问你一句，可选，推荐设；在终端里配对时必须有）；

它要报告问题时，会先把原文给你看。你同意，才发。见 [广场与反馈](/docs/plaza-feedback/)。

## 每一步在做什么

下面的编号和 `install.md` 一样。标了 ✋ 的步骤整步都要你动手，没标的步骤里也可能有一两处要叫你。

### 第 1 步：核对安装说明

下载安装说明，核对两件事：网站公布的校验值对得上，网站那份和 GitHub 公开那份一字不差。对不上它会停下来告诉你，不会继续装。

### 第 2 步：准备好反馈

AI 先开一个反馈通道，以后哪一步出了问题，可以把问题报给我们。开通道时不带任何内容，我们只看到你Agent J 主机的 IP 和时间。之后每次发反馈，它都会先把原文给你看。

### 第 3 步：检查Agent J 主机环境

AI 会检查你的系统，看看 `curl`、`git`、`uv` 在不在。Linux 上还要查 bubblewrap，Mac 不用装，系统自带。它也会看哪些 AI 编程工具已经装好并登录了。至于你用 iPhone 还是安卓，等到第 11 步要用时再问。

Ubuntu 24.04 还会检查 AppArmor 对用户命名空间的限制，并实际试启动一次隔离。限制值是 `1` 不一定有问题：只要 bubblewrap 的专用权限配置已生效，隔离就能正常运行。缺少 bubblewrap 时需要你确认安装；如果权限仍被拦住，诊断会给出只放行 `/usr/bin/bwrap` 的 `/etc/apparmor.d/bwrap-agentj` 配置步骤。已有配置不会自动覆盖，也不会关掉整个系统的限制。安装助手会在启动后台服务前检查；没通过就暂停并保留续装记录，修好后重跑原命令即可。具体命令见 [安装说明](https://agentj.app/install.md) 的云服务器一节。

这一步可能要你动手：

- 装 bubblewrap 或别的系统软件时，输入你的Agent J 主机密码；
- Claude Code 或 Codex 没登录时，在你自己的终端里登录；
- 在中国大陆，或者一个能用的都没有时，AI 会帮你装 OpenCode。模型账号要你自己去模型厂商那里注册、充值、建 key，再在你自己的终端里运行 `opencode auth login` 把 key 存好。AI 不会碰你的 key，也不会问你要。

### 第 4 步：安装 agentj 程序

AI 安装Agent J 主机端程序 `agentj`，装的是固定的一个版本：

```bash
uv tool install "git+https://github.com/preangelleo/agentj@v0.25.19a1#subdirectory=host"
agentj doctor
```

`agentj doctor` 会逐行检查，告诉你哪些已就绪、哪些还没好。如果 GitHub 太慢或打不开（比如在中国大陆），AI 会自动改从我们网站下载同一个程序，先核对校验值再安装。

装好以后，你自己的终端也要能找到 `agentj`，因为第 8 步和第 11 步要你自己运行它。新开的终端找不到的话，AI 会先问你能不能运行 `uv tool update-shell`：它会在你终端的启动文件里加一行。你同意了它才运行，之后新开一个终端窗口就能用。不想改启动文件，就在要用的终端里先输入 `export PATH="$HOME/.local/bin:$PATH"`，或者新开一个终端试试。

### 第 5 步：生成这台Agent J 主机的身份

```bash
agentj init
```

这一步给这台Agent J 主机生成它自己的钥匙。钥匙只存在这台Agent J 主机上，谁也不该去碰它，包括 AI。

### 第 6 步：✋ 注册账号、买席位

如果你发给 AI 的那句话里有设置码（别人给你付的席位），**跳过这一步**：钱已经付了，你不用注册，也不用付款。

否则，AI 会请你：

1. 用浏览器打开账号后台 https://agentj.app/account ，在Agent J 主机上或手机上都行。填邮箱，点「发送验证码」，把邮件里的 6 位验证码填在网页上，点「登录」。验证码 10 分钟内有效，邮件来自 noreply@mail.agentj.app，没收到就看看垃圾邮件。验证码只填在网页上，别发给 AI。
2. 按网页提示点「在这台设备上创建通行密钥」，用指纹、面容或屏幕锁确认。要在收到验证码后 10 分钟内做完。Linux 遥控器浏览器一般没有自带的通行密钥：在弹出的窗口里选用手机（扫一下屏幕上的二维码），或者用 USB 安全钥匙；更简单的办法是这一步直接在手机上做。
3. 「团队名称（选填）」可以不填，点「开通账号」。
4. 在「账单」里买 1 个席位：选「月付」或「年付」，「买几个席位」填 1；有优惠码或邀请码就填在「优惠码或邀请码（可不填）」里；点「购买席位」，到 Stripe 的页面付款。价格和优惠码的规矩见 [账号与付款](/docs/account/)。
5. 付完回到账号后台，在「空席位」卡片上点「复制安装提示词」，把这句话发给Agent J 主机上的 AI。它就接着往下装了。

Stripe 付款页上的价格是美元，商户名是 AgentJ.app。第一次付款后 7 天内不想用了，可以全额退款。付完回到账号后台，如果页面让你登录：钱已经付成功了，用通行密钥或邮箱验证码再登录一次就好，别再付一次。

### 第 7 步：✋ 把这台Agent J 主机加到账号里

AI 先问你：这个 Agent 叫什么名字？比如「小助手」「店铺助手」，或者你自己起的名字。长度最多 13：中文每个字算 1.6，英文字母、数字、空格和符号每个算 1，也就是纯中文最多 8 个字、纯英文最多 13 个字母。然后它用那句话里的设置码，把这台Agent J 主机加到账号的这个席位上，再把加入的是哪个账号告诉你。请你核对一下账号 ID，不对的话它会马上退出来。用完以后，它会把存设置码的那个临时文件删掉。

安装提示词不能用时，回到同一张空席位卡再次复制，会签发新的七天单次码，并作废之前未使用的码。旧八位码入口已经退役，重试不要再买一个席位。

### 第 8 步：✋ 用账户页通行密钥批准

第一台遥控器只有两个入口：账号页席位卡「添加遥控器」，或自己在终端运行 `agentj pair`。本地 127.0.0.1 设置页只给账号页跳转。账号页出二维码后保持打开，扫码后自动显示等待配对的遥控器、六位确认码和「批准」按钮；核对两边一致再批准。之后的遥控器打开 https://m.agentj.app 自助申请，由已配对遥控器扫码、核对并批准。

安装结束时会问你要不要设遥控器配对密码（可选，推荐）：直接回车就跳过，以后随时运行 `agentj passphrase set`。Agent 不能替你选择或输入。在终端里配对（`agentj pair`、`agentj pair --link`）必须有这个密码，没设的话 `agentj pair` 会先请你设；`agentj pair --check` 会在出二维码之前告诉你现在走哪条路。


### 第 9 步：接上 AI 编程工具

AI 先把自己能查的都查清楚，再用一条短消息一次问你，只问必须你拍板的事。每一项都标好推荐，你回一句「好」就全按推荐办。

- **用哪个 AI 编程工具。** `agentj agent detect --json` 会列出能用的。只有一个能用就直接用它，不问你；有两个以上，它列出来让你选。只有这一项不给推荐，因为它不替你挑。
- **Agent 在哪个文件夹里干活。** 它先找你平时放项目的文件夹（比如 `~/coding`），找到就推荐它；没有就推荐新建 `~/coding`。第一次用，新建一个空文件夹（比如 `~/agentj-work`）也行。然后运行：

```bash
agentj agent claude --dir ~/agentj-work
```

用 Codex 就把 `claude` 换成 `codex`。用 OpenCode 还要写上模型：

```bash
agentj agent opencode --dir ~/agentj-work --model zhipuai/glm-5.3
```

Agent 会在一个隔离的环境里运行：用你自己的登录和设置，但碰不到 `agentj` 自己的钥匙和设置。AI 还会看看你Agent J 主机上有没有开着会认你身份的本地服务（比如浏览器的调试端口），用一句话告诉你隔离挡不住什么。

它不会问你浏览器里有没有登录邮箱、购物网站或银行。原因是这样的：手机上的 Agent 以你的身份干活，如果这台Agent J 主机上有浏览器开着调试端口，Agent 就能操作它，用上里面所有已登录的网站。但在任何网站上付款、下单、转账，都一定会先停下来，到手机上问你，不管你登录了什么，所以问了也不会改变什么。真有这样的端口开着，AI 会点名告诉你。

它还会装上「工作流设计向导」，配对好以后，你在手机上说「帮我设计工作流」就能用。

这一步有两件事 AI 一定会做，不会跳过：问你 Agent 在哪个文件夹里干活；单独发一条消息，告诉你隔离挡不住什么。你看过了它再往下走。

### 第 10 步：让它一直运行

```bash
agentj service install
```

装成系统服务后，Agent J 主机开机登录后它会自己启动，不用你每次手动开。装完 AI 会运行 `agentj doctor`，把以 `!` 开头的每一行用人话告诉你。常见的一种：Claude Code 只靠环境变量登录，后台服务拿不到这个登录。这时你在终端里运行一次 `claude` 正常登录，再让 AI 重装一次服务就好。在云服务器上，AI 可能会请你运行一次 `loginctl enable-linger $USER`（可能要输密码），这样你退出 SSH 后它也照样运行。

### 第 11 步：✋ 配对手机

配对之前，Agent J 主机上的 Agent J 要在运行（第 10 步）。

4. 经账户页批准的配对不需要终端六位码，等手机连上即可。

Agent J 主机离线或账户页添加遥控器已关闭时（`agentj pair --check` 会告诉你），用本机备选：运行 `agentj pair`（或 `agentj pair --link`），在那台Agent J 主机上输入手机六位码和遥控器配对密码（还没设会先请你设一个）。

### 第 12 步：在手机上试一试

AI 会请你在手机上：

1. 发一句「列出这个文件夹里有什么」，看能不能收到回复；
2. 让它建一个测试文件再删掉。手机上会弹出卡片，按住「长按批准」大约一秒，按钮填满再松手。删除要你单独点头，所以那张卡片标着 ⚠，按钮照样是「长按批准」。用 Codex 的话，它会告诉你会看到什么；
3. 想要锁屏提醒的话，点「开启锁屏提醒」。

然后 AI 会问你要不要给我们发一条「装完了」的反馈，写用了多久、哪里不顺。发之前先给你看原文，你说不发就不发。

### 第 13 步：交接

最后，AI 运行 `agentj handover --lang zh`，把这台Agent J 主机上填好真实信息的交接说明原样转给你：Agent 名、账号 ID、配了哪些手机、手机上打开 https://m.agentj.app 、丢了手机怎么办（`agentj devices` 找到设备号，再 `agentj revoke <设备号>`）、忘了遥控器配对密码怎么办（它只存在这台Agent J 主机上；有已配对的手机用 `agentj passphrase reset --phone`，手机确认后在终端输新密码，所有手机保持配对；没有就用 `agentj passphrase reset`，所有手机都要重新配对）、有新版本怎么升级、「恢复」「定时任务」「命令」在哪、怎么退款、卸载不等于取消订阅。这段话是程序写的，AI 不改、不加命令。

它还会问你：要不要把「先查文档」这条规矩记到它的长期记忆里。你同意的话，它会自己运行 `agentj docs-rule --write`，程序把这条规矩加到 AI 记忆文件的末尾（只加一次），并给你看加了什么。记下以后，你在新的对话里问它 Agent J 的事，它会先查这些文档，查不到再帮你问我们。手机上的 Agent 本来就知道这条规矩。

## 装到一半想停下

直接告诉 AI 先停。它会问你要不要把停在第几步报给我们（同样先给你看）。下次再把那句话发给它，从头核对一遍再继续就行。

想全部卸掉，在终端里运行：

```bash
agentj service uninstall
uv tool uninstall agentj
```

这样只会卸掉 Agent J 自己的程序，不会动你的 Claude Code、Codex、OpenCode，也不会动 Agent 的工作文件夹。卸载不会停止扣费：席位和订阅要在账号后台的「管理账单」里取消，见 [账号与付款](/docs/account/)。


每个已付费且未绑定的席位各可领取一张安装码。两个空余付费席位可领两张码；未使用码作废或过期后可重领，仍受安装服务日额度限制，UTC 零点重置。

## 从其他设备给席位添加遥控器

第一台遥控器只有两个入口：账号页席位卡「添加遥控器」，或自己在终端运行 `agentj pair`。本地 127.0.0.1 设置页只给账号页跳转。账号页出二维码后保持打开，扫码后自动显示等待配对的遥控器、六位确认码和「批准」按钮；核对两边一致再批准。之后的遥控器打开 https://m.agentj.app 自助申请，由已配对遥控器扫码、核对并批准。

默认允许账户页添加；目标Agent J 主机的主人可用 `agentj remote-pair off` 关闭。离线时不排队，开机后重试；旧版本按提示运行 `agentj update apply` 或从已有手机升级。新设备来源显示「经账户页添加」，其他遥控器收到通知。

账户页配对依赖签名控制平面。配对材料只以浏览器临时公钥加密回传，后端不保存明文；签名服务被攻破仍可能增加设备，关闭开关可拒绝此路径。遥控器配对密码只在那台Agent J 主机上散列保存。在账户页输入它时，浏览器先用那台Agent J 主机临时给出的一次性公钥把它加密，只有那台Agent J 主机能解开、核对；我们的服务器只转发看不懂的密文，也不保存。连续输错 5 次，那台Agent J 主机会锁定一段时间。


## macOS 系统版本

先试运行 `opencode --version`（或所选 Agent 的 `--version`）；能正常运行就能继续安装，不按 macOS 版本号拦截。一键安装也会实际试运行它下载的固定版 OpenCode。如果看到 `dyld: Symbol not found: _ubrk_clone` 和 `/usr/lib/libicucore.A.dylib` 后退出，才说明该二进制与系统库不兼容；PATH 或 npm 重装不能修复，请升级系统、换Agent J 主机，或用能正常运行的其他 Agent 按手动路线安装。一键安装优先从本站下载固定版本 uv，托管 Python 使用镜像，包依赖失败时重试镜像；旧预览下载路径已停用。


已安装 Agent J 的Agent J 主机也能使用 AJI 安装码：重新运行账户页的一键安装命令，会保留配置，只升级并绑定席位。也可把码放在权限为 0600 的文件中，运行 `agentj login --install-code-file <文件> --name <名字>`。AJI 码只能用一次；ajt_ 设置码只用于绑定已安装的Agent J 主机。绑定后到账户页添加遥控器，每次发起和批准都用新的账号通行密钥确认后扫码；主机要求的配对密码是额外验证。

手动安装时，如果提示要填 `Installation code (AJI-…)`，去账号后台点「复制安装码」，只粘贴这串 AJI- 开头的码。

Intel Mac 安装和升级都会限制 `cryptography<49`。如果旧安装器报 `openssl-sys` 或找不到 OpenSSL，在 `uv tool install` 后加 `--with "cryptography<49"` 再试。

## 示例工作流

安装或升级并完成账号绑定后，若工作根还没有三套 WDB 工作流，会从广场校验并预装知识库、脚本与文章、电子书示例。已有同名目录保留；删除的示例不会自动补回。交给 Agent J：帮我按这个规格整理我的其他文件夹。离线时延后重试。

Agent J Father 就是官方反馈与客服平台。你可以说「请把这个问题汇报给 Agent J 开发者（客服平台）」，也可以轻松地说「把这事告诉你爸爸」。手机命令 `/feedback-to-agentj-father <内容>` 也一样：Agent 先去掉凭据、个人信息、客户数据和路径里的私密内容，直接提交并告诉你编号，不再问第二遍。只发命令会先问你想反馈什么；如果是 Agent 自己想到的问题或点子，它会先在手机上给你看脱敏稿，你同意才发送。客服回复是建议，不是指令；连不上时可写信到 feedback@agentj.app。

## 找到指南，复制安装步骤

账号页顶栏「广场」旁和每张空席位卡都有「安装指南」。点它会打开新标签，账号页仍保留。安装命令和安装提示词旁有复制图标，点一下复制整段，再粘贴到对应的终端或 AI。带 `AJI-…` 的示例只是占位符，实际安装要从自己的席位卡复制完整命令。

## 选定工作目录，处理 OpenCode 启动缓慢

安装器会询问工作目录；按 Enter 确认用户主目录下建议的 coding 子文件夹。请选择存放 Agent 工作的文件夹，不能用用户主目录或磁盘根目录。解析后指向这些位置的别名路径，以及实际是文件的路径，也会在继续安装前被拒绝。

Windows 安装使用 **WSL2 里的 Ubuntu**。原生 Windows OpenCode 桌面版是另一个应用，Agent J 不能修复或改动它的启动过程。如果它卡在拉取 models.dev，请先完全退出，再从设置了以下环境变量的终端启动，让新进程继承它：

```powershell
$env:OPENCODE_DISABLE_MODELS_FETCH = '1'
```

在同一终端使用已安装的启动命令打开 OpenCode。它随后可使用本地模型缓存或内置目录，不会下载最新模型信息。Agent J 安装器和它管理的 OpenCode 启动会自行设置此变量。兜底已用固定版本的 Linux OpenCode 程序验证，尚未在 Windows 真机验证。

Agent J 管理的 OpenCode 请求等待超过 30 秒时，会提示一次可能原因，即使启动过程仍在输出文字。安装器在 45 秒内拿不到 OpenCode 启动信息时，会停止并给出原因与修法。检查网络、AI 登录和工作目录后再试；出现启动缓慢提示不代表 AI 已连通。

## 安全审核（Jev）的三种选择

初始化时请先选一种审核方式；没填 key 也没选择时，`agentj onboarding` 会提示继续设置。推荐到 [TypeSafe](https://typesafe.ai) 注册账号、创建 key、充值少量金额，在「模型和 API Key」靠上的 Jev 区域用密钥卡填写 `TYPESAFE_API_KEY`。已有 [OpenRouter](https://openrouter.ai) 账号，也可填写 `OPENROUTER_API_KEY`。已有 key 会自动沿用（同时存在时沿用 OpenRouter），也能在 设置 → 安全 选择来源。

Jev 会给客服、好友消息增加模型审核，也会复查脱敏内容、辅助审批判断；必要的脱敏文本直达所选服务商，费用由你的账号承担。TypeSafe 走官方接口，OpenRouter 走其中的 Jev 模型，两者受各自的数据政策约束。模型可能误判，也会增加延迟。选择的服务不可用时保留该通道的失败处理，不会自动变成关闭。

你也可在 设置 → 安全 关闭总开关，明确确认「跳过，我知道安全性会弱一点」。主机会记录 `jev.mode=off`、签名设备与确认时间。关闭后所有 Jev 模型审核都跳过，客服和好友流程可继续；本地正则、凭据过滤、权限审批和工具授权仍保留。关闭可减少延迟与误拦，同时失去这层防护。即使有 key 也能关闭。Agent 不能代签或通过改配置自行关闭；只有主人在已配对手机上的签名选择才生效，签名设备被解绑后这份关闭授权失效。

macOS「登录项与扩展」中的 Agent J 使用带名字、图标和开发者签名的 App。主机保持手机连接；救援守护在主机卡住时提供救援，建议都保持开启。每周任务按各自时间运行，可停用不需要的任务。升级会重写主机与救援登录项，并迁移旧的每周通知任务；若提示签名 App 下载失败，联网后运行 `agentj service install` 重试。


第一台遥控器只有两个入口：账号页席位卡「添加遥控器」，或自己在终端运行 `agentj pair`。本地 127.0.0.1 设置页只给账号页跳转。账号页出二维码后保持打开，扫码后自动显示等待配对的遥控器、六位确认码和「批准」按钮；核对两边一致再批准。之后的遥控器打开 https://m.agentj.app 自助申请，由已配对遥控器扫码、核对并批准。

**首台遥控器，按你的情况选：**
- **有账号**：打开 `agentj pair --check --json` 返回的 `account_url`，在这台主机的席位卡点「添加遥控器」，扫码后核对六位码并批准。
- **只有席位**：请你本人在主机终端敲下面这一行：`agentj pair`。你亲自设置并输入遥控器配对密码（至少 8 位），再输入遥控器显示的六位码；AI 不得代设、读取或代输密码。
- **账号是别人开的**：请公司的账号负责人在账号页批准。没有账号、又不愿操作终端时，请负责人协助。

`agentj pair` 默认同时显示二维码与链接；`--link` 保留兼容。方法一：手机扫码。方法二：把同一个链接粘到电脑浏览器地址栏直接打开。链接 5 分钟、一次有效，是配对密钥，不要发给别人或 AI；iPhone 请粘到主屏幕图标内的配对链接框。

**首台配好后**：手机先配 → 建议在常用电脑浏览器打开 https://m.agentj.app，用已配对手机扫电脑显示的码，核对后在手机确认；电脑先配 → 建议在电脑「设置 → 遥控器管理 → 添加遥控器（配对新遥控器）」打开二维码，用主力手机扫码，核对后在电脑确认。两台都配好并验收首条消息再结束安装。

## 从旧版本升级

普通主机先运行 `agentj update apply`，再核对 `agentj --version` 和 `agentj doctor`。只有命令不存在或旧更新器失败时，才到账户席位卡复制当前安装命令，在同一系统用户、同一实例上重跑。配置与绑定保留，不要 unlink、删除状态或另建席位。Olares Market 应用仍从 Market 升级。

## 自动升级没成功怎么办 {#upgrade-failed}

下载、校验或安装准备失败时，Agent J 会提示仍是原版本。先让你的 Agent 运行 `agentj doctor` 看原因，不要删除配置、解绑账号或重新建席位。

如果升级后已经回滚，旧版程序能运行就会记为回滚成功；后台服务或自检仍有问题时会单独列出，继续处理这些问题即可。旧更新器只有成功安装新版后才能得到这些改进。旧版 uv 安装仍无法升级时，在电脑终端按 [旧更新器自救步骤](/docs/faq/) 运行当前安装器的修复升级命令；不需要新安装码，保留配置和绑定。Olares Market 应用通过 Market 升级。

## 首次启动 AI 失败 {#first-ai-start}

把报错里的 `AJ_START_*` 原因码留给你的 Agent，让它运行 `agentj doctor --offline`。如果是后台环境问题，先在手机设置里检查模型代理；安装 AI 命令行工具后，运行 `agentj service install` 更新服务配置，再检查一次。

已有火山方舟、阿里百炼或 Kimi 账号，可以继续用原来的服务商。服务商设置会直接打开手机密钥卡；已有密钥会复用，不需要重复提交。等卡片确认完成后再切换模型，密钥不要发进聊天。


## 从桌面 App 安装后找不到 Agent

从 ChatGPT 等桌面 App 里安装也可以。后台服务会使用登录终端里的稳定程序路径，并补上常见的用户安装目录，不会记住 App 里的临时路径。如果终端能运行 Claude Code，Agent J 却说没装，先运行 `agentj doctor`；它提示服务路径缺少程序时，运行一次 `agentj service install` 修复，再检查一次。这个操作会重启 Agent J，手机会短暂断开后自动重连；不需要重新安装 Claude Code，也不要把登录文件或密钥发到聊天里。
## OpenCode 版本兼容 {#opencode-compatibility}

Agent J 会自动选择 OpenCode 1.x 或 2.x 对应的连接方式，已在隔离环境测试 1.19.4 和 2.1.4。已有 1.x 可以继续用，Homebrew 装的 2.x 不必降级。升级 OpenCode 不要求清空对话；只有你想另开对话时才清空。

启动或切换失败时，在主机运行 `agentj doctor`。Agent J 会先检查本地服务能否启动，再完成切换。另一个只处理私聊、不开放工具的执行器需要旧版命令行的 `--dir` 参数；OpenCode 2.1.4 没有这个参数，会在启动私聊进程前拒绝。这个通道可改用受支持的 Claude Code 或 Codex 执行器。

只读应急诊断先试当前免费列表里的 DeepSeek Flash，再试 `opencode/glm-5.3-flash-free`（当天官方模型页须明确承诺不留存、不训练），最后才用你明确安装的本地 Ollama 模型。LongCat 和 Space Bunny 不进入兜底顺序。每次重新核实可用性，不自动选付费模型，也不重发原任务。云端诊断只收到固定错误信号。

OpenCode 2.1 已移除旧的详细模型列表命令。Agent J 会自动读取原生价格目录来识别免费模型，不要求你运行那个旧命令。安装器先使用Agent J 主机核实的模型列表，再试模型能否回复。
