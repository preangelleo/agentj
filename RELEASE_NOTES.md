## Changes

- Open enabled cards from their first Chinese or English name in an Agent reply.
- See the paired remote count in Settings and remote management.
- Use consistent selection colours throughout the editors.
- Show verified tool, model, reasoning level and running time as small grey task details.
- Share action policy across owner, external channel, friend and support requests; require fresh passkey verification for opaque commands.
- Reuse one dedicated browser per seat and keep closed windows closed. Seats retain separate profiles; seats2+ start headless and show a window only for explicit open or host sign-in.
- Repair older updaters missing uv with install-assistant --upgrade-only, keeping configuration and the existing seat.
- Stop add-seat previews and confirmations above the one-seat remaining-period ceiling, protecting old promotional seats from repricing; complete incremental promotion billing remains follow-up work.
- Refresh pairing hints and setup checklists after pairing, removal and reconnect without reloading.
- Open real key input cards on the initiating remote from Settings, and reopen them after collapsing.
- Confirm email settings with a clear summary, then open app-password input directly and show connection results. Gmail hides server settings.
- Enter missing safety-review keys directly, with provider-specific card titles and restored diagnostic-card spacing.
- Agent 回复首次提及已开启卡片时，中英文卡名自动变成入口。
- 设置和遥控器管理显示已绑定遥控器数量。
- 编辑器选中文字的配色保持一致。
- 在办事项用小号灰字显示已核实的工具、模型、思考档位和运行时间。
- 统一主人、外部通道、好友和客服的动作策略；无法看清的命令每次都需通行密钥确认。
- 专用浏览器启动串行复用，关窗后不自动重开；多席位各自保留登录资料，2号起默认后台运行，明确打开或电脑登录时才显示。
- 旧版升级器缺失 uv 时，可运行 install-assistant --upgrade-only 安全修复升级；不重新配置、不更换席位。
- 新增席位的预览或确认金额超过单席剩余期上限时停止处理，避免旧促销席位被重新计费；完整促销增量计费仍待后续完善。
- 配对、解绑后提示和安装清单实时更新，重连后自动核对，无需刷新页面。
- 修复设置页点击填写密钥却未弹出输入窗的问题；输入窗绑定当前遥控器，收起后可再次打开。
- 邮件设置先用清晰摘要确认改动，再直接打开授权码输入卡；保存后显示连接测试结果。Gmail 不显示服务器设置。
- 安全审核缺少 Key 时可直接填写，密钥卡按服务商标明用途；画面诊断卡间距恢复。

## Material acceptance limits

- Android arbitrary-name wake recognition, false-accept/false-reject rates, background operation,
  battery behavior and speech-model licensing are not cleared for a released app.
- Paid-provider sound and cost are unverified; no complete voice catalogue or hardware benchmarks.
- Cross-format migration and power-loss recovery remain unproven; no 99% first-boot AI success claim.
- Telegram input can be dropped after an offset failure; output has no durable retry queue.
- iOS background hotword listening is unsupported.
