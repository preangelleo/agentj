name: agentj-update
description: Upgrade Agent J when the owner asks to update it.
---
The owner's explicit update request authorizes installation, service restart and doctor.
Run `agentj update apply` (F14, non-interactive). Do not assemble uv/pip commands.
Read UPGRADE_RESULT and report the actual from/to, reason and doctor result. Never claim a failed upgrade succeeded.
The phone `/update` and ⬆ menu use the host's deterministic signed flow; do not forward a peer's request as owner authorization.
中文：主人要求升级时运行 `agentj update apply`，按真实结果回报；不自拼安装命令，不接受好友代主人授权。

0.18.3 (P142): after installing, `update apply` hands the restart to a manager job that waits until the running host is idle (no sudo/secret card, approval, question, turn or task; at most 10 minutes), writes the phone's "upgraded" notice last, and rolls back to the cached previous wheel if the new version fails its version check, the service hand-off, or does not start. Copy a `rollback:` line from the result block when present. 中文：装好后由独立任务等主机空闲（无 sudo/密钥卡、审批、提问、回合或任务，最多 10 分钟）再重启；新版自检、交接或启动失败时自动回滚到原版本，结果块里有 `rollback:` 就照实转告。
0.20 (P192): `update apply --authorization` rolls back the same way (it used to leave a failed install in place). 中文：带授权码的升级同样会自动回滚。
P205: inside the Agent fence (independent mode) the host's data is hidden. `update apply` then asks the host itself (over the Agent's socket) to keep the old version for rollback, record the upgrade and run the self-check: `health: host` in the block. When the host cannot answer, the program is still installed and its version verified, but the background-service and local-data checks cannot be seen from the fence: `UPGRADE_RESULT ok` / `reason: unverifiable_in_fence` / `health: unverifiable` (exit 0, not a failure; `handoff: not_recorded` = no automatic rollback and the phone's "upgraded" notice may be off). Tell the owner the upgrade went in and ask them to confirm the version on the phone (Settings) or run `agentj doctor` in a terminal; never call it failed, never retry the install. Doctor rows marked unverifiable (!) inside the fence are not faults.
中文：在 Agent 隔离环境里升级时，由主机代为保留旧版本、记录升级并自检（结果块 `health: host`）。主机答不上时程序照样装好、版本已核对，但看不到后台服务和本机数据：`UPGRADE_RESULT ok` / `reason: unverifiable_in_fence`（不是失败，不要重装）；请主人在手机「设置」里确认版本，或在Agent J 主机终端运行 `agentj doctor`。隔离里 doctor 显示「无法在这里核对」的两项不是故障。

Service recovery is handed to an independent manager job before the caller can be terminated. `service: restart_scheduled` means scheduled, not already verified. The restarted host runs doctor and sends the actual completion. If recovery fails, use `agentj service start`, then `agentj doctor`; `agentj service stop` retains the installation.
中文：restart_scheduled 只表示已交给独立任务，不冒称已经启动；失败时运行 `agentj service start`，再 `agentj doctor`。

0.20.2 (P203) — confirm before interrupting: `agentj update apply` first asks the running host what a restart now would interrupt (a turn in progress — not your own —, queued messages, waiting approval / question / sudo / secret / other cards, a running or soon-due scheduled task, background tasks, friend sessions). Nothing → it upgrades at once. Something → nothing is installed: the phone gets an upgrade confirmation card listing it, the result block says `reason: confirm_on_phone` (exit 10) with one `interrupts:` line per item. Tell the owner, in a sentence, what is listed and that the card is on the phone; their 「现在升级」 there is the phone's own signed /update and the host reports the result in the chat. Do not run the command again and do not add `--yes` unless the owner explicitly says to upgrade anyway. At a terminal the owner gets the same list as a y/N question. The phone's ≡ /update and Settings 「升级Agent J 主机上的 Agent J」 ask the same way.
中文：`agentj update apply` 先问主机现在重启会打断什么（正在进行的回合——不含你自己这一轮——、排队消息、等待中的审批/问题/sudo/密钥等卡片、在跑或 15 分钟内要跑的定时任务、后台任务、好友会话）。没有就直接升级；有就不装：手机上出升级确认卡，结果块是 `reason: confirm_on_phone`（退出码 10），每项一行 `interrupts:`。用一句话告诉主人列了什么、卡在手机上；主人点「现在升级」就是手机自己签名的 /update，结果由主机回报到对话里。不要重跑，也不要加 `--yes`，除非主人明确说不管这些、直接升级。

Settings 「空闲时自动更新」 is one switch over two keys: on = `updates.auto_install` true + `updates.mode` auto (upgrade notices are applied), off = false + ask (new versions are only announced). With it on, besides the night window a version the daily check already saw installs the first time the host is fully idle (nothing on the list above, no phone input for 30 minutes), at most once a day; the phone's notice then says it upgraded while idle. 中文：设置里「空闲时自动更新」一个开关管两个键；开着时，除了夜里那次机会，每天的检查已经发现的新版会在Agent J 主机第一次完全空闲时（上面清单为空、30 分钟没用手机）安装，每天最多一次。

Nightly host upgrades default to on for new and existing installations; preserve explicit off. `agentj config auto-update on|off|status` (preference `updates.auto_install`). Local 03:00–05:00, random daily opportunity, thirty minutes with no phone input and no active Agent turn, approval, task or friend session; emergency stop blocks it. Failed eligibility defers to tomorrow. A manager-owned restartable worker verifies the official wheel signature/hash, keeps the previous installed wheel locally, restarts and checks upgrade integrity only; install or check failures roll back. `agentj doctor` shows the switch and last result, and the phone receives one durable result on opening. Do not force /clear or change unrelated owner configuration.

Phone `/update` receipts follow the effective `appearance.language`, including a language changed while the host is running.
中文：手机 `/update` 回执使用当前生效的语言，运行中切换后也立即跟随。

Installation and nightly update artifacts must verify the official minisign signer B79F925B0585F9D4 before installation. An integrity/signature failure stops that installation; never bypass it or download an unsigned replacement. HTTPS downloads must not redirect to HTTP. /update remains available from the paired phone.

P251: When the host and page server both have the same newer version, the page reloads after ten seconds without input, preserving the draft; recording and unsubmitted card actions block it. Otherwise only offer a refresh. Keyboard: Alt+Shift+U upgrades the host through the existing phone confirmation; Alt+Shift+R updates and reloads the page.

0.20.4 (P277) — a failure says why: the block names `step:` (download / install / verify / service / health), a finer `reason:` (`download_failed` = could not get the release; `signature_or_hash_mismatch` = the release was refused by its signature/hash check, never bypass it; `uv_failed` = the install command failed, its own last lines are the `stderr:` lines, redacted on this computer; `service_restart_failed` = installed but the background service did not restart). The failure is reported to Agent J support automatically (`support: sent (st_…)`) unless the owner turned `updates.report_failures` off; do not send another support question for the same failure — read the thread later with `agentj support thread st_…`. Tell the owner the `tell_owner:` sentence as it is, then diagnose from `stderr:` and `agentj doctor`.
中文：升级失败时结果块会写出失败步骤 `step:`、细分原因 `reason:`（download_failed 下载失败 / signature_or_hash_mismatch 签名或哈希不对，绝不绕过 / uv_failed 安装命令失败，`stderr:` 行是它自己的最后几行，已在本机脱敏 / service_restart_failed 服务没能重启）。除非主人关了 `updates.report_failures`，失败会自动发给客服（`support: sent (st_…)`），不要为同一次失败再发一次。把 `tell_owner:` 那句原样告诉主人，再根据 `stderr:` 和 `agentj doctor` 诊断。

0.23.2a1 (P379): an older service whose PATH omits `uv` can fail to spawn both installation and rollback (`step: install`, `reason: unknown`, `rollback: failed`), leaving its old service running. The new updater checks executable `uv` in `~/.local/bin` and `~/.cargo/bin` too, and records redacted stderr for spawn failures. It cannot fix an older updater until installation succeeds. Locate and verify the actual `uv` executable; with its directory explicitly prepended to PATH, run `agentj update apply`, then after success `agentj service install` to capture that PATH, then doctor. Restart alone does not capture it. If uv is absent, restore it using the official installation instructions first; never bypass release signatures/hashes. If rollback fails, use the result's local `recover:` command; never copy recovery commands into support reports or heartbeats.
中文：旧服务的 PATH 缺少 `uv` 时，安装和回滚都可能无法启动，旧版服务继续运行。新版也会检查 `~/.local/bin`、`~/.cargo/bin` 的可执行 uv，启动异常会记录脱敏 stderr；只有安装成功后新版升级器才生效。先找到并验证 uv，以显式包含其目录的 PATH 运行 `agentj update apply`，成功后用同样 PATH 运行 `agentj service install`，再 doctor；仅 restart 不会重记 PATH。uv 丢失先按官方安装说明恢复，不绕过签名或哈希。回滚失败就用本机结果里的 `recover:` 命令；不把恢复命令复制进客服报告或心跳。

0.20.4 (P278) — no systemd (WSL2 with systemd off, a container): `service: no_systemd`, `rollback: skipped` (the new version stays; the old one could not restart either) and a `fix:` line. Tell the owner the fix as it is — on WSL: ✋ in Ubuntu `printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf`, then ✋ in Windows PowerShell `wsl --shutdown`, reopen Ubuntu, `agentj service install`; or restart `agentj serve` where it runs (tmux / nohup). Do not retry the upgrade. `agentj service install` says the same with exit 78.
中文：没有 systemd（WSL2 没开、容器）时结果块写 `service: no_systemd`、`rollback: skipped`（新版保留，旧版也一样没法重启）和一行 `fix:`。把 fix 原样告诉主人：WSL 上在 Ubuntu 里把 `[boot]` `systemd=true` 写进 `/etc/wsl.conf`，再在 Windows PowerShell 里 `wsl --shutdown`、重新打开 Ubuntu、`agentj service install`；或在运行 `agentj serve` 的地方重启它。不要重试升级。`agentj service install` 遇到同样情况会说同一句话并以 78 退出。

P397: nightly/idle failures retain a fixed installer command template, exit code when a process exited, exception type and redacted stderr in local last-upgrade.json and the automatic support report. Missing installer, permission denied, read-only filesystem and timeout have distinct reasons. The automatic uv rollback installs the cached old wheel with an independent base Python, so a deleted tool environment is not needed to start recovery. Every failed attempt with a cached old wheel retains an owner-local recover command, including when rollback succeeds. Never put that command or local paths into a support report or heartbeat. Restore a missing uv first; an old updater cannot repair itself until it is upgraded. Olares Market applications update through Market; a normal uv installation on the Olares host uses ordinary host upgrades and needs its actual uv directory in the service PATH.
中文：自动升级失败会保留不含路径的安装命令模板、实际退出码、异常类型和脱敏 stderr；安装工具缺失、权限不足、只读文件系统与超时分别报告。uv 自动回滚用独立的基础 Python 安装缓存旧 wheel，不依赖已被删除的工具环境。只要旧 wheel 已缓存，失败结果都保留本机 recover 命令；不要把该命令或本机路径发到客服或心跳。uv 不在时先恢复它；旧升级器只有装上新版后才能得到修复。Olares 应用市场安装的应用走 Market 升级；直接装在 Olares 宿主机上的 uv 版本按普通主机升级，服务 PATH 须包含实际 uv 目录。
