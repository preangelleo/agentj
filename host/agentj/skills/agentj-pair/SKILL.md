# Pair a remote on the owner's computer

1. Read the matching language's pairing section in `https://agentj.app/install.md` downloaded as a local file. During installation, account binding is an intermediate step, not completion.
2. Actually run `agentj devices --json`. If no remote is paired, proactively guide the owner through pairing before reporting installation complete.
3. Before any pairing step, actually run the pre-check `agentj pair --check --json` (read-only; no link, QR or code). Its `route` is the same rule `agentj pair` and `agentj admin` use, so the owner never gets stuck at the last step: `account` → step 3 below (account page: passkey or the remote pairing password); `passphrase` → the terminal route is ready; `set_passphrase` → tell the owner the one sentence it prints (offline, or `remote-pair off`): they run `agentj pair` themselves in their own terminal, which asks them to set the remote pairing password first — or fix the reason and use the account page; `seat` (0.20.0) → this computer has no usable Agent J seat (not bound, suspended, or unconfirmed for more than 72 hours): no route pairs anything — bind it first (`agentj login --seat-file …` with the account page's installation prompt) or have the owner renew on the account page it names.
   For an account-bound online host (`account`), tell the owner: on its account-page seat card choose **添加遥控器 / Add a remote**, confirm it's them and scan with the new remote. This works from another computer. Confirming is either a passkey (reused for ten minutes on this session) or this computer's **遥控器配对密码 / remote pairing password** typed in the card (0.20.3, P221): an email-code sign-in never approves a remote by itself, so on a computer without a passkey the owner uses the password, or in the browser prompt chooses **使用手机或平板 / Use a phone or tablet**, or adds the remote from an already paired phone (设置 → 遥控器管理 → 添加遥控器). The password is sealed in the browser to a one-time key of this computer and only this computer checks it (5 wrong in a row lock it here for a while). If the card says this computer has no password and the owner has neither a passkey nor a paired phone, the one way left is the card's own sentence: back at this computer, `agentj pair` in their terminal (it asks them to set the password first). Pending remotes can also be reviewed and approved on that card. If the card stops with a reason (computer not picking up / online but silent / clock more than 5 minutes off), follow it and press **重试 / Try again**; for a silent online computer check `agentj doctor` and update Agent J.
4. Pairing secrets are generated on the target host and encrypted to the account browser, never visible to the Dashboard backend. Never read, log, relay or request a link/QR/password. Only the owner performs the passkey ceremony or types the password. Pairing at the terminal (`agentj pair`, `agentj pair --link`, approving on `agentj admin`) always needs the remote pairing password (0.20.3, P221 — the 0.20.0 "a bound computer's keyboard is enough" rule is gone): without one, `agentj pair` first asks the owner to set it (at least 8 characters), then takes the phone's six-digit code at its prompt 「输入手机上显示的 6 位安全码」 (3 tries) plus the password; the account page may approve at the same time, the first one wins. An Agent's shell or a pipe can neither set it nor approve (`agentj pair` there stops before any QR code), so never run `agentj pair` yourself to approve. An unbound host cannot pair at all (0.20.0): bind the seat first. From 0.20.0 a remote that is already paired can add the next one itself: Settings → 遥控器管理 / Remotes → 添加遥控器 / Add a remote shows a one-time QR and link; the new device's 6-digit code is typed on that remote (PROTOCOL §24) or confirmed on any paired remote's card. The other way round also works (0.20.0, P190, PROTOCOL §27): the new device opens https://m.agentj.app and shows its own code at the top; the owner scans it with a paired remote (top-right scan icon, 「扫码添加遥控器」, or holding the camera button), both screens show the same 6 digits, the owner taps 「一致」 on the paired remote — nothing to type on the computer. Tell the owner to scan only a code on a device in front of them. Each Agent holds up to 10 remotes. `agentj remote-pair off` disables account-page and remote-side additions and owner approvals. Offline hosts are not queued; older hosts must upgrade first. If the seat card says the computer is busy with another pairing: tapping 添加遥控器 again takes over an earlier unscanned account-page QR, 「取消上一次，重新生成二维码」 also ends a forgotten `agentj pair` (never a phone mid-pairing); on hosts older than 0.20 wait until the time it shows, or run `agentj pair --link` in the terminal, which always replaces an account-page QR.
5. Verify a real remote is listed and send the first message from it. Only then finish installation. Do not introduce pairing as an extra permission lock on ordinary tasks.
6. Two remotes are required (F28): ① this computer's browser (open https://m.agentj.app here and pair it from its account seat card), then ② the owner's main phone (Home Screen icon → 「扫二维码」). Run `agentj onboarding` (or `--json`) after each step; it shows the seat, both remotes and the welcome. Pair other phones, pads or computers only when the owner asks. If the phone cannot read the QR code (F29): let the code fill most of the middle of the camera view, brighten the screen; after 10 s the phone's scanner suggests the fallback itself — the owner runs `agentj pair --link` in their own terminal and pastes the link into the Home Screen app (or, in a browser tab, scans with the phone's Camera app). The link is the pairing key: never ask for it, never relay it.
6a. Remote over SSH (no desktop, or the owner is away from the screen): recommend starting and finishing in the same SSH terminal — the owner runs `agentj pair --link` (it asks them to set the remote pairing password first if there is none), opens the link on the phone by their own means, then types the phone's 6-digit code at the terminal prompt and the password. Digits typed after the command ended go to the shell; after 「120 秒内没有批准」 they run `agentj pair --link` again and open the new link. Never ask for the link, the code or the password.
7. After the first pairing, Agent J asks the main Agent to write the first message on that remote (who it is, the first remote is ready, talk here from now on, then a short tour one step per owner reply). It happens once; later remotes get one line. Tell the owner to look at the new window instead of repeating it in the terminal.
8. Moving a seat to a different computer needs fresh pairing. History stays on the old computer.
9. Once one remote is paired, every later one is easiest from that remote (P153): on it, **设置 → 遥控器管理 → 添加遥控器 / Settings → Remotes → Add a remote** shows a QR (5 min, one use); the new device scans it and shows 「已申请，请在任意一台已绑定的遥控器上确认」 with a 6-digit match code; every paired remote gets a 「有新遥控器申请绑定」 card with the same code — the owner holds 确认 on any one (Face ID first if that remote has one), the others fold — or types the code into the 遥控器管理 page that made the QR and taps 批准 (P171). No passphrase. The same card also appears for a terminal `agentj pair` / account-page pairing. Tell the owner to compare the two codes and to tap 取消 if they differ. Never confirm on the owner's behalf. If `agentj pair` exits with 「✗ 手机断开了」 the new device left and that link is spent: the owner runs `agentj pair` again (or uses 遥控器管理 → 添加遥控器 on a paired remote).
10. 「打开 Agent 管理页」「管理页」「admin 页」「配对页面」 / "open the admin page", "pairing page" = run `agentj admin --open` (P163, 0.20.0): it opens the local admin page in this computer's default browser and returns at once; the one-time link never reaches your output. If it answers that no browser can be opened here (SSH, no desktop), the owner runs `agentj admin` in their own terminal. During installation step 11, when the admin page did not open by itself, offer this in one sentence.
11. The unpaired phone page [https://m.agentj.app/](https://m.agentj.app/) (「连上你的Agent J 主机」 / "Connect to your computer", P210, 0.20.2) is numbered cards — the owner picks one: 「方法一」 a paired remote scans the code shown on this device (both screens show the same 6 digits, tap 「一致，加为遥控器」 on the paired one); 「方法二」 run `agentj pair` in the computer's terminal (macOS Terminal; Windows PowerShell / Windows Terminal; Linux terminal) and tap 「扫二维码」, or `agentj pair --link` and paste the printed `https://` link into that card's link box; 「方法三」 the account dashboard seat card → 「添加遥控器（手机或浏览器）」 → passkey → scan. 「以前在这台设备上配过？」 at the bottom (Face ID) is reconnecting, not a new pairing. When guiding the owner, name the card and the device each step happens on.

账号管付钱，席位管功能。一个邮箱一个账号；一个账号可以买多个席位。手机或浏览器叫「遥控器」，Agent 是绑定席位的Agent J 主机或服务器。

0.16.1 defaults to the compact numeric pairing link (smaller QR); AGENTJ_PAIR_COMPACT=0 selects legacy JSON. Both are secrets and only the owner may use them.

Account passkey approval also offers resume after Stop everything and enabling a specific scheduled task. The Agent must never perform owner confirmation itself or lift the owner’s stop. The remote pairing password is optional but recommended (`agentj passphrase offer` asks once at the end of an installation, Enter skips; `agentj passphrase set` later — the owner types it, never you); pairing at the terminal requires it.
