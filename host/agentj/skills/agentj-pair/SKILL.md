# Pair a remote on the owner's computer

1. Read the matching language's pairing section in `https://agentj.app/install.md` downloaded as a local file. During installation, account binding is an intermediate step, not completion.
2. Actually run `agentj devices --json`. If no remote is paired, proactively guide the owner through pairing before reporting installation complete.
3. Before any pairing step, actually run the pre-check `agentj pair --check --json` (read-only; no link, QR or code). Its `route` selects the account-page or terminal route; the local admin page only links to the account page, so the owner never gets stuck at the last step: `account` → step 3 below (account page: passkey or the remote pairing password); `passphrase` → the terminal route is ready; `set_passphrase` → tell the owner the one sentence it prints (offline, or `remote-pair off`): they run `agentj pair` themselves in their own terminal, which asks them to set the remote pairing password first — or fix the reason and use the account page; `seat` (0.20.0) → this computer has no usable Agent J seat (not bound, suspended, or unconfirmed for more than 72 hours): no route pairs anything — bind it first (`agentj login --seat-file …` with the account page's installation prompt) or have the owner renew on the account page it names.
   For an account-bound online host (`account`), tell the owner: on its account-page seat card choose **添加遥控器 / Add a remote**, confirm it's them and scan with the new remote. This works from another computer. Confirming is either a passkey (reused for ten minutes on this session) or this computer's **遥控器配对密码 / remote pairing password** typed in the card (0.20.3, P221): an email-code sign-in never approves a remote by itself, so on a computer without a passkey the owner uses the password, or in the browser prompt chooses **使用手机或平板 / Use a phone or tablet**, or adds the remote from an already paired phone (设置 → 遥控器管理 → 添加遥控器). The password is sealed in the browser to a one-time key of this computer and only this computer checks it (5 wrong in a row lock it here for a while). If the card says this computer has no password and the owner has neither a passkey nor a paired phone, the one way left is the card's own sentence: back at this computer, `agentj pair` in their terminal (it asks them to set the password first). After scanning, the page automatically shows the waiting remote, six-digit code and Approve. Compare and approve; never require a manual Review waiting remotes click. Password fallback verifies the password again, sealed to a fresh host key with the exact waiting device/handshake. If the card stops with a reason (computer not picking up / online but silent / clock more than 5 minutes off), follow it and press **重试 / Try again**; for a silent online computer check `agentj doctor` and update Agent J.
4. Pairing secrets are generated on the target host and encrypted to the account browser, never visible to the Dashboard backend. Never read, log, relay or request a link/QR/password. Only the owner performs the passkey ceremony or types the password. Pairing at the terminal (`agentj pair`, `agentj pair --link`, the owner approving at the terminal) always needs the remote pairing password (0.20.3, P221 — the 0.20.0 "a bound computer's keyboard is enough" rule is gone): without one, `agentj pair` first asks the owner to set it (at least 8 characters), then takes the phone's six-digit code at its prompt 「输入手机上显示的 6 位安全码」 (3 tries) plus the password; the account page may approve at the same time, the first one wins. An Agent's shell or a pipe can neither set it nor approve (`agentj pair` there stops before any QR code), so never run `agentj pair` yourself to approve. The password lives only on that host, never on our server. Forgotten: with a paired phone the owner runs `agentj passphrase reset --phone` in their own terminal (the phone confirms, the new one is typed there, every remote stays paired; it refuses an Agent's shell); with none, `agentj passphrase reset` unpairs every remote. An unbound host cannot pair at all (0.20.0): bind the seat first. From 0.20.0 a remote that is already paired can add the next one itself: Settings → 遥控器管理 / Remotes → 添加遥控器 / Add a remote shows a one-time QR and link; the new device's 6-digit code is typed on that remote (PROTOCOL §24) or confirmed on any paired remote's card. The other way round also works (0.20.0, P190, PROTOCOL §27): the new device opens https://m.agentj.app and shows its own code at the top; the owner scans it with a paired remote (top-right scan icon, 「扫码添加遥控器」, or holding the camera button), both screens show the same 6 digits, the owner taps 「一致」 on the paired remote — nothing to type on the computer. Tell the owner to scan only a code on a device in front of them. Each Agent holds up to 10 remotes. `agentj remote-pair off` disables account-page and remote-side additions and owner approvals. Offline hosts are not queued; older hosts must upgrade first. If the seat card says the computer is busy with another pairing: tapping 添加遥控器 again takes over an earlier unscanned account-page QR, 「取消上一次，重新生成二维码」 also ends a forgotten `agentj pair` (never a phone mid-pairing); on hosts older than 0.20 wait until the time it shows, or run `agentj pair --link` in the terminal, which always replaces an account-page QR.
5. Verify a real remote is listed and send the first message from it. Only then finish installation. Do not introduce pairing as an extra permission lock on ordinary tasks.
6. Pair the owner's main phone and usual computer browser in either order. After phone first, open https://m.agentj.app in the usual computer browser; the paired phone scans that code, compares six digits and approves. After computer first, use Settings → Remotes → Add a remote on that computer; the phone scans, compare six digits and confirm on the computer. Run `agentj onboarding --json` after each. Pair other devices only when asked. `agentj pair` shows both QR and link by default; `--link` is a compatibility option. Never ask for or relay the link.

6a. Remote over SSH (no desktop, or the owner is away from the screen): recommend starting and finishing in the same SSH terminal — the owner runs `agentj pair --link` (it asks them to set the remote pairing password first if there is none), opens the link on the phone by their own means, then types the phone's 6-digit code at the terminal prompt and the password. Digits typed after the command ended go to the shell; after 「120 秒内没有批准」 they run `agentj pair --link` again and open the new link. Never ask for the link, the code or the password.
7. After the first pairing, Agent J asks the main Agent to write the first message on that remote (who it is, the first remote is ready, talk here from now on, then a short tour one step per owner reply). It happens once; later remotes get one line. Tell the owner to look at the new window instead of repeating it in the terminal.
8. Moving a seat to a different computer needs fresh pairing. History stays on the old computer.
9. 之后的遥控器打开 https://m.agentj.app 自助申请，由任意已配对遥控器扫码、核对六位码并批准（P190 反向配对）。Never confirm for the owner. Settings → Remotes → Add a remote remains available on paired remotes.
10. 「打开管理页」 / "open settings" means `agentj admin --open`. 「配对页面」 / "pairing page" means the account page. Local 127 settings only links there; never start first pairing there.
11. The unpaired phone page [https://m.agentj.app/](https://m.agentj.app/) (「连上你的Agent J 主机」 / "Connect to your computer", P210, 0.20.2) is numbered cards — the owner picks one: 「方法一」 a paired remote scans the code shown on this device (both screens show the same 6 digits, tap 「一致，加为遥控器」 on the paired one); 「方法二」 run `agentj pair` in the computer's terminal (macOS Terminal; Windows PowerShell / Windows Terminal; Linux terminal) and tap 「扫二维码」, or `agentj pair --link` and paste the printed `https://` link into that card's link box; 「方法三」 the account dashboard seat card → 「添加遥控器（手机或浏览器）」 → passkey → scan. 「以前在这台设备上配过？」 at the bottom (Face ID) is reconnecting, not a new pairing. When guiding the owner, name the card and the device each step happens on.

账号管付钱，席位管功能。一个邮箱一个账号；一个账号可以买多个席位。手机或浏览器叫「遥控器」，Agent 是绑定席位的Agent J 主机或服务器。

0.16.1 defaults to the compact numeric pairing link (smaller QR); AGENTJ_PAIR_COMPACT=0 selects legacy JSON. Both are secrets and only the owner may use them.

Account passkey approval also offers resume after Stop everything and enabling a specific scheduled task. The Agent must never perform owner confirmation itself or lift the owner’s stop. The remote pairing password is optional but recommended (`agentj passphrase offer` asks once at the end of an installation, Enter skips; `agentj passphrase set` later — the owner types it, never you); pairing at the terminal requires it.

P444b installation contract (中文 / English): 先运行 `agentj pair --check --json`，打开返回的 `account_url`；首台遥控器只有账号页「添加遥控器」和主人终端 `agentj pair` 两个入口。扫码后账号页自动显示等待中的遥控器、六位确认码与「批准」，主人核对后点批准。不要打开本地 127 页配对；已在等待中时不要重新配对。Run the check, open account_url, choose Add a remote, scan, compare the automatically displayed six-digit code and approve. Do not open the local admin page for installation pairing. If a phone is already waiting, approve that waiting phone on the same seat; do not restart pairing. Later devices request at m.agentj.app and a paired remote approves. Password fallback asks for the owner’s password again when approving, sealed to a one-use host key and bound to the waiting device/handshake; never ask the owner to tell you the password or code.

## 安装收尾 / Installation handoff

**首台遥控器，按你的情况选：**
- **有账号**：打开 `agentj pair --check --json` 返回的 `account_url`，在这台主机的席位卡点「添加遥控器」，扫码后核对六位码并批准。
- **只有席位**：请你本人在主机终端敲下面这一行：`agentj pair`。你亲自设置并输入遥控器配对密码（至少 8 位），再输入遥控器显示的六位码；AI 不得代设、读取或代输密码。
- **账号是别人开的**：请公司的账号负责人在账号页批准。没有账号、又不愿操作终端时，请负责人协助。

`agentj pair` 默认同时显示二维码与链接；`--link` 保留兼容。方法一：手机扫码。方法二：把同一个链接粘到电脑浏览器地址栏直接打开。链接 5 分钟、一次有效，是配对密钥，不要发给别人或 AI；iPhone 请粘到主屏幕图标内的配对链接框。

**首台配好后**：手机先配 → 建议在常用电脑浏览器打开 https://m.agentj.app，用已配对手机扫电脑显示的码，核对后在手机确认；电脑先配 → 建议在电脑「设置 → 遥控器管理 → 添加遥控器（配对新遥控器）」打开二维码，用主力手机扫码，核对后在电脑确认。两台都配好并验收首条消息再结束安装。

**First remote — choose your situation:**
- **Own account**: open `account_url` returned by `agentj pair --check --json`, choose Add a remote on this host's seat card, scan, compare the six digits and approve.
- **Seat only**: type this line yourself in the host's terminal: `agentj pair`. Set and enter your own remote pairing password (at least 8 characters), then enter the remote's six digits; AI must never set, read or type the password for you.
- **Someone else opened the account**: ask the account manager to approve on the account page. If you have no account and prefer not to use the terminal, ask that manager for help.

`agentj pair` shows both QR and link by default; `--link` remains compatible. Way 1: scan with your phone. Way 2: paste the same link into a computer browser's address bar. The link is a pairing key, valid for 5 minutes and one use; never share it with anyone or an AI. On iPhone paste into the pairing-link box inside the Home Screen icon.

**After the first remote**: phone first → open https://m.agentj.app in your usual computer browser, scan its code with the paired phone, compare and confirm on the phone; computer first → on the computer open Settings → Remotes → Add a remote, scan with your main phone, compare and confirm on the computer. Finish installation after both remotes and the first message are verified.
